# Тестовое задание для tile.expert

Тестовое задание на позицию Middle PHP-программист для компании tile.expert.

Приложение синтетическое и не акцентирует внимание на сложной бизнес логике.
Приложение демонстрирует работу с Docker, Symfony, создание REST и SOAP API,
покрытие тестами реализацию поиска с Manticore.

## Техническое задание

Необходимо создать простое приложение и приложить ссылку на архив или
Git-репозиторий (предпочтительнее).

Приложение должно собираться при помощи docker-compose (можно добавить 
сборку-запуск через make) и отвечать на http запросы.

Порты настраиваются в переменных окружения.

Приложение должно отвечать (эндпоинты описать в readme, идеальнее в сваггере):

- Эндпоинт №1 - при GET запросе с параметрами
  `factory=marca-corona&collection=arteseta&article=k263-arteseta-camoscio-s000628660`
  выводить цену в евро со страницы
  https://tile.expert/it/tile/marca-corona/arteseta/a/k263-arteseta-camoscio-s000628660.
  Другие значения фабрики, коллекции, артикула должны отдать правильную цену.
  Ответ в виде json
  `{"price": 59.99,"factory": "marca-corona","collection": "arteseta","article": "k263-arteseta-camoscio-s000628660"}`;
- Эндпоинт №2 - при GET запросе с пагинацией (страница, количество на странице)
  и группировкой. Отдать json с количеством заказов по месяцам, годам, дням.
  В ответе данные о станице, количестве на странице, количестве страниц итд и
  основная нагрузка - группирирующее значение и количество;
- Эндпоинт №3 (2? см REST API) - при SOAP запросе - сохранить (создать) данные.
- Эндпоинт №4 - получение одного заказа.

Добавить возможность поиска через Мантикору (*).

Приложение должно быть покрыто основными тестами.

Необходимо описание что не так в таблице БД, как её улучшить. Приложить
улучшенный дамп.

В гит-хистори должны быть коммиты с этапами выполнения задания.

дамп https://gitlab.com/tile-expert-test-tasks/backend/-/blob/main/dump.sql

## Первый запуск

Для упрощения работы с приложением используется утилита make.
В ней описаны ряд целей для упрощения запуска и работы с приложением.

Для первого запуска можно использовать команду:

```bash
make install
```

Данная команда развернёт контейнер с приложением, установит зависимости,
запустит миграции и заполнит базу фикстурой, сгенерирует отчёт о покрытии.

По умолчанию приложение запустится по адресу: http://localhost

Документация REST API: http://localhost/api/doc

Структурой SOAP запросов: http://localhost/soap/doc/

Отчёт о покрытии: http://localhost/coverage/index.html

## Реализация

При реализации я соблюдал историчность коммитов, что-бы история git отражала
этапы выполнения задания. Для улучшения качества кода я использовал статический
анализатор [phpstan](https://phpstan.org/user-guide/getting-started). Для
соблюдения единого стиля кода я использовал
[php-cs-fixer](https://cs.symfony.com/doc/installation.html).
Я старался обеспечить высокий уровень покрытия тестами. Формировал и сверялся
с отчётом покрытия тестами.

### Улучшенный дамп

> Необходимо описание что не так в таблице БД, как её улучшить. Приложить
> улучшенный дамп.
>
>Исходный дамп: [dump.sql](https://gitlab.com/tile-expert-test-tasks/backend/-/blob/main/dump.sql)

Я не стал делать улучшенный дамп. Проблема в структуре дампа понятна: таблица
`order` имеет избыточную разряженную структуру, большинство полей nullable.
Структура данных нуждается в нормализации. Однако корректно сделать это, имея
на руках только дамп нельзя, т.к. нельзя однозначно точно установить взаимосвязи
между полями. Какие поля существуют только вместе, а какие заполняются независимо?
Для выполнения этого задание, кроме дампа базы данных, необходимо иметь описание
бизнес процессов, которые должна описывать эта модель.

### Эндпоинт №1

> При GET запросе с параметрами
> `factory=marca-corona&collection=arteseta&article=k263-arteseta-camoscio-s000628660`
> выводить цену в евро со страницы
> https://tile.expert/it/tile/marca-corona/arteseta/a/k263-arteseta-camoscio-s000628660.
> Другие значения фабрики, коллекции, артикула должны отдать правильную цену.
> Ответ в виде json
> `{"price": 59.99,"factory": "marca-corona","collection": "arteseta","article": "k263-arteseta-camoscio-s000628660"}`;`

Реализовал точка входа которая получает данные напрямую с https://tile.expert:

```
GET /api/v1/articles/by-filter
```

Для получения данных я использовал существующую API:

```
https://tile.expert/en-us/slideshow-json/{factory}/{collection}/a/{article}
```

### Эндпоинт №2

> При GET запросе с пагинацией (страница, количество на странице) и группировкой.
> Отдать json с количеством заказов по месяцам, годам, дням. В ответе данные
> о станице, количестве на странице, количестве страниц итд и основная нагрузка 
> группирирующее значение и количество.

Реализовал точку входа:

```
GET /api/v1/orders/count
```

Главной сложностью стала группировка данных по датам. По умолчанию в Doctrine
нет методов для форматирования даты, но я добавил пакет `beberlei/doctrineextensions`,
в составе которого есть методы `DATE_FORMAT`, `LAST_DAY`, которые я использовал
для группировки данных.

### Эндпоинт №3

> При SOAP запросе - сохранить (создать) данные.

Самоё сложное из всех заданий. Главная проблема - отсутствие современных
инструментов для работы с SOAP.

Symfony по определению - это REST фрэймворк. Из коробки он не поддерживает SOAP.
Для реализации SOAP API я использовал
[laminas/laminas-soap](https://docs.laminas.dev/laminas-soap/).
Пришлось написать довольно много инфраструктурного кода. Я не стал покрывать
тестами инфраструктурный код.

Я проигнорировал создание `orders_article`.

Я реализовал SOAP сервис:

```
/soap/v1/orders
```

В котором реализовал два метода `createOrder` и `updateOrder`.

SwaggerUI плохо подходит для документации SOAP. Для документации SOAP API я
использовал [wsdl-web](https://github.com/wsdl-web/wsdl-web).

### Эндпоинт №4

> Получение одного заказа.

Самое простое и очевидное из всех заданий.

Я проигнорировал возврат `orders_article`.

Для получения заказа я реализовал точку входа:

```
GET /api/v1/orders/{orderId}
```

### Поиск через Мантикору

> Добавить возможность поиска через Мантикору (*).

Для развёртывания Manticore я использовал Docker-контейнер
[manticoresearch/manticore](https://hub.docker.com/r/manticoresearch/manticore)
и библиотеку
[manticoresoftware/manticoresearch-php](https://github.com/manticoresoftware/manticoresearch-php).
Библиотека не реализует интеграцию с Symfony, поэтому пришлось написать много
инфраструктурного кода. Я не стал покрывать тестами инфраструктурный код.

Для поиска через Manticore я реализовал точку входа:

```
GET /api/v1/orders/search
```

Для заполнения и обновления Manticore я реализовал команду:

```bash
bin/console app:manticore:populate
```

Я не стал реализовывать онлайн синхронизацию. Создание новых заказов не приведёт
к автоматическому добавлению новых записей в Manticore.
